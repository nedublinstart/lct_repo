# Алгоритм (черновик для питча и доработки)

Сервис строит **до трёх содержательно разных вариантов** за один запуск.

## Вариант 1. Раздельное подключение

Каждый перспективный ОКС независимо:

1. Берёт точку подключения на границе.
2. Снэпается на ближайшую точку существующей сети (участок или камера).
3. Ищет путь A* по сетке, обходя `AVOID`-ограничения.
4. Сглаживает ломаную (string pulling), чтобы не было «лесенки».
5. Если врезка не в камере — ставит новую камеру.

Это безопасный базовый план и запас, если совместная сеть не собирается.

## Вариант 2. Совместное подключение

Узлы: все ОКС + виртуальный узел «существующая сеть».

Рёбра:

- ОКС ↔ ОКС — путь A* между точками подключения;
- ОКС ↔ сеть — путь до ближайшей врезки.

Дальше **MST (Прим)**. Расходы текут по дереву к врезке и суммируются на общих участках. Это как раз требование кейса про совместные ОКС.

## Вариант 3. Врезка в существующие камеры

Как вариант 1, но цель — существующая камера, а не середина трубы. Обычно дороже по длине, дешевле/проще по врезке. Нужен, чтобы показать, что варианты отличаются не сдвигом на метр.

## После геометрии

1. Подбор минимального DN по расходу.
2. Если длина «нитки» одного DN больше `max_run_m` — DN поднимается.
3. Доп. расход от врезки идёт по `next_id` к источнику.
4. Если требуемый DN существующего участка больше фактического — реконструкция.
5. Стоимость: новые трубы, камеры, врезки, спецпроход, реконструкция, штраф за неподключённые ОКС.
6. Score = `0.7 * cost + 0.3 * length * length_to_cost` (веса из YAML, формулу заменят из официального приложения).

## Глубина (доп. задача)

Отдельный режим `DEPTH`. XY считается заново тем же движком, затем каждому новому участку назначается Z: не мельче нормы DN и ниже пересекаемых коммуникаций с зазором. Это не проверка 2D-трассы, как просит ТЗ.

## Что усилить к финалу

- Растр с адаптивным окном / visibility graph вместо равномерной сетки.
- Запрет самопересечений новой сети: слияние в узел.
- Угол пересечения дорог после построения (сейчас дорога — повышенная стоимость клетки).
- Стейнер / несколько кандидатов врезки, не только nearest.
- Не зашивать ID и координаты конкурсного набора.
