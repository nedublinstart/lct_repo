# Алгоритм

Сервис строит **до трёх содержательно разных вариантов** за один запуск. Правила, таблицы DN и стоимости читаются из `config/appendix.yml` (официальное техническое приложение).

Расчёты длин, буферов и сетки — в **EPSG:32637** (UTM 37N). Вход и выход GeoJSON остаются WGS 84.

## Подготовка сцены

1. Потоковый разбор FeatureCollection. `object_type` из приложения: `source`, `heat_network`, `heat_chamber`, `oks_future`, `oks_connection_point`, `oks_existing`, `restriction`.
2. Если нет полигонов `oks_future`, точка `oks_connection_point` с `flow_tph` сама становится перспективным ОКС (как в конкурсном наборе).
3. Если нет `upstream_object_id`, топология существующей сети восстанавливается Дейкстрой от источника по стыковке концов участков и камер (окно 4 м).
4. Ограничения: `oks` / `water` / `railway` — обход (`AVOID` + буфер). Дороги, ТДТП и коммуникации — спецпроход (`SPECIAL`, коэффициент `k_spec`).

## Дороги и ТДТП

Строителям нельзя вести теплосеть вдоль проезжей и срезать улицу диагональю. Алгоритм:

1. Явные полигоны `road` / `tdtp` / `tram_tracks` / `carriageway` становятся полосами проезжей. Ось — длинная сторона минимального прямоугольника.
2. Если дорог во входе нет (как в конкурсном наборе), проезжая **синтезируется** из щелей 7–52 м между кварталами: середина улицы — спецполоса, 3.5 м у фасада остаются тротуаром.
3. Ребро графа видимости вдоль фасада — обычная прокладка. Через проезжую разрешено только пересечение с углом ≥ 45° к оси дороги (лучше ~90°). Продольный ход и длинная диагональ запрещены (стоимость +∞ / штраф сетки ×6.5).
4. На выдаче спецметод ставится **только на сам проход** (+ `extend_m` по 3 м с каждой стороны). Подходы по тротуару — `laying_method=base`. На стыках — `technical_node`.

Пути: граф видимости по фасадам (взвешенный A*), запас — сетка с направленной стоимостью шага, string pulling не имеет права вернуть диагональ через дорогу.

## Точки подключения внутри зданий

Конкурсные ИТП лежат **внутри** полигонов существующих ОКС. Труба не может стартовать в запретной клетке:

- для каждого ИТП ищется ближайшая свободная точка на улице (граница буфера здания + спираль);
- от ИТП до этой точки добавляется короткий ввод (последние метры через «своё» здание);
- дальше A* идёт только по свободным коридорам.

Вдоль существующей теплосети пробит коридор 3.5 м, чтобы врезка была достижима даже на участке, пересекающем ж/д.

## Вариант 1. Совместное дерево

1. Кандидаты врезки: существующие камеры со степенью &lt; 4 и точки на трубе каждые ~30 м (не ближе 10 м к камере).
2. Выбор врезки: сумма расстояний от уличных портов ОКС, бонус камере, **штраф**, если DN существующей трубы не держит суммарный расход (чтобы не реконструировать зря).
3. ОКС сливаются **агломеративно**: ближайшая евклидова пара, для которой найден путь, соединяется новой камерой на середине трассы. У камеры 2 входа + 1 выход → степень 3 ≤ 4.
4. Корень дерева одним участком садится на выбранную врезку. Если врезка не камера — ставится новая камера.

Пути: вдоль фасадов и короткие спецпроходы через проезжую (см. раздел «Дороги и ТДТП»).

## Вариант 2. Врезка в существующую камеру

То же дерево, но цель — ближайшая допустимая тепловая камера (правило 10 м и 4 примыкания).

## Вариант 3. Два куста

ОКС делятся плоскостью через центроид и самую дальнюю точку. У каждого куста своё дерево и своя врезка. Если кустов не получается (мало ОКС) — запасной вариант «каждый ОКС к ближайшей точке сети».

## После геометрии

1. Минимальный DN по `flow_tph` из таблицы приложения; если длина нитки больше `max_run_m` — DN поднимается.
2. Доп. расход от врезки идёт по восстановленному `next_id` к источнику.
3. Если требуемый DN существующего участка больше фактического — `heat_network_reconstruction` по `recon_per_m`.
4. Стоимость новой трубы: `L × c_new × K_spec × K_depth`. Камеры — по порогам DN. Врезка — 5 000 000 ₽. Штраф неподключённого ОКС: `100 000 000 + 500 000 × G`.
5. Рейтинг (чем меньше, тем лучше):  
   `S = 0.7 × (C / 25 000 000) + 0.3 × (L / 100)`.

Выход — один FeatureCollection на все варианты (`variant_id` 1..3) плюс те же три файла по отдельности.

## Глубина (доп. задача)

Режим `DEPTH`. XY считается тем же движком, затем участку назначается Z не мельче нормы DN и ниже пересекаемых коммуникаций.
