# Техническая аннотация

Аннотация расчёта `engine.flow.FlowRoutingEngine`. Формулы, смета и границы совпадают с [`MODEL.md`](MODEL.md) и с кодом. Таблицы DN, Kспец, горизонтальные расстояния, камеры, штраф и веса S читаются из `config/appendix.yml` (техническое приложение от 26.09.2026).

## 1. Что считает сервис

На вход один GeoJSON. На выход один GeoJSON: до трёх вариантов, диаметры, стоимость и показатель S. Совместное или раздельное подключение выбирает поиск.

Ручной чертёж в CAD оставляет маршрут инженеру. ГИС эксплуатации ведёт уже построенную сеть. Трассировка по осям улиц заставляет трубу идти вдоль дорог. Здесь маршрут строится по полигонам входного файла: граф видимости, лес подключений, смета приложения и, в отдельном запуске, профиль глубины. Улицы подложки карты в модель не входят. Координаты конкурсного набора в код не зашиты.

## 2. Граф видимости

Вершины — выпуклые углы раздутых запретов и выходы ИТП. Ребро — битангента. Кратчайший путь среди этих многоугольников проходит по таким рёбрам, поэтому замена непрерывной ломаной графом оптимум по длине на них не теряет.

Контур упрощается на 0,3 м и для графа раздувается ещё на 0,3 м, поэтому проверка строже точного отступа таблицы 2. Это оптимум длины на построенных многоугольниках. Глобальный минимум S по всем допустимым трассам из этого не следует: в цель входят камеры, диаметры и предельный пробег, а поиск ограничен бюджетом.

Вес ребра — не чистая длина. Спецпроход входит в вес до выбора маршрута:

\[
\tilde L(ab) = L(ab) + \sum_z (K^{\mathrm{спец}}_z - 1)\, L^{\mathrm{спец}}_z(ab).
\]

Недопустимый спецпроход получает вес \(+\infty\). Наложение нескольких спецзон даёт максимум \(K^{\mathrm{спец}}\). Дорога, трамвай, газ, кабель и существующая теплосеть без врезки пересекаются одним прямым участком. Угол \(\ge 45^{\circ}\) задан для дороги и трамвая. Для существующей теплосети отдельной нормы угла нет; в поиске врезка не идёт вдоль трубы, синус угла к оси не меньше 0,5.

## 3. Вес метра из показателя S

\[
S = 0{,}7 \cdot \frac{C}{25\,000\,000} + 0{,}3 \cdot \frac{L}{100}.
\]

\[
\lambda_0 = \frac{0{,}3 / 100}{0{,}7 / 25\,000\,000} = 107\,142{,}857\ldots \text{ ₽/м}.
\]

При \(K^{\mathrm{гл}} = 1\)

\[
S = \frac{0{,}7}{25\,000\,000}\,(C + \lambda_0 L).
\]

Множитель положителен, поэтому у режима минимальной стоимости порядок по цели \(J\) совпадает с порядком по S. В карточку и в файл пишется C по смете приложения. Веса поиска в эту C не входят.

## 4. Три цели

\(U\) — число неподключённых точек, \(M = 10^{15}\). \(N_{\mathrm{врезок}}\) — число новых участков, входящих в места присоединения.

| режим | цель \(J\) |
|---|---|
| минимальная стоимость | \(C + \lambda_0 L + M \cdot U\) |
| минимум врезок | \(C + \lambda_0 L + 50\,000\,000 \cdot \max(0,\, N_{\mathrm{врезок}} - 1) + M \cdot U\) |
| минимальная длина | \(C + (\lambda_0 + 100\,000\,000)\, L + M \cdot U\) |

Добавка 50 млн ₽ за лишнюю врезку и 100 млн ₽ за метр укорочения живут только в поиске. В смете врезка в существующую камеру — 5 000 000 ₽ за каждый новый участок, который в ней заканчивается. Отдельной платы за врезку в трубу нет: на трубе ставится новая камера.

\(M\) больше любой связной сметы. Найденный маршрут сохраняется. Точка остаётся без сети только если допустимого маршрута нет. В файл и в S тогда пишется штраф приложения: \(100\,000\,000 + 500\,000 \cdot G_i\).

Подпись «Минимальная стоимость» ставится на вариант с наименьшим S. Вариант короче остальных остаётся, даже если его S выше.

Когда вес длины равен \(\lambda_0\), две первые очереди сборки дополнительно считаются с удвоенным весом метра и затем оцениваются уже по S. Иначе поиск остаётся в лесу, который не стал короче, но вырос в диаметре и камерах.

## 5. Смета перед выдачей

Поиск внутри окна группы пользуется суррогатом: метр стоит \(c(DN(G_S)) + \lambda\), камера — по этому же DN, предельного пробега и монотонности DN относительно всего леса в динамике нет. Перед выдачей лес пересчитывается полной сметой.

\[
C_{\mathrm{трубы}} = \sum_{e} L_e \, c(DN_e) \, K^{\mathrm{спец}}_e \, K^{\mathrm{гл}}_e.
\]

\[
C = C_{\mathrm{трубы}} + C_{\mathrm{камеры}} + C_{\mathrm{врезки}} + P, \qquad L = \sum_e L_e.
\]

Новая камера берётся по наибольшему DN примыкающих участков и уже включает присоединение: 3 / 5 / 8 / 12 млн ₽ при DN до 200 / 500 / 1000 / 1400. Реконструкция существующей сети не выполняется и в C и L не входит.

DN участка не меньше DN по расходу и не меньше DN ниже по дереву. Непрерывный путь одного DN, включая камеру без смены DN, не длиннее предельного пробега таблицы 1. Технический узел без смены DN пробег не обнуляет. Если предельный пробег поднимает DN выше DN, по которому строился коридор, отступ и габарит пересчитываются.

## 6. Каскад поиска

Бюджет по умолчанию 12 с на все выбранные режимы. Это свойство `heatnet.flow.budget-ms`, не срок из задания. В задании предела длительности нет. Четверть бюджета остаётся на последний проход по чистой цели S. Из оставшихся трёх четвертей минимальная стоимость получает долю 2, каждый другой режим — долю 1. Поиск останавливается по бюджету и отдаёт лучший уже найденный лес. Построение графа в эти 12 с не входит. На конкурсном наборе граф около 1700 вершин и 6500 рёбер, зоны и граф вместе меньше секунды.

1. Несколько начальных лесов. ОКС вставляются по очереди: ближе к сети, по расходу, дальше от сети и несколько случайных порядков. Лист подвешивается туда, где приращение \(J\) меньше.
2. Локальный поиск переподвешивает поддеревья. Из верхней точки отсоединённого поддерева идёт Дейкстра по \(\tilde L\). Кандидат отсекается, когда уже пройденная длина стоит больше лучших. Несколько лучших пересчитываются точной сметой.
3. Группа до 8 соседних ОКС снимается и строится заново внутри окна с запасом 120 м. Динамика Дрейфуса — Вагнера даёт оптимальное дерево группы в окне по суррогату. Время на группу из \(k \le 8\) ОКС, \(w\) вершин и \(e\) рёбер — \(O(3^k w + 2^k (e + w \log w))\). Восемь — размер окна динамики, не ограничение числа ОКС в лесу: на конкурсном наборе в лесу все 17 точек.
4. Камера разветвления сдвигается итерациями Вайсфельда. Вес соседней вершины — цена метра трубы её DN. Рёбра заменяются кратчайшей допустимой ломаной между теми же концами.
5. Итерированный локальный поиск чередует перестройку группы и перевставку листьев до конца бюджета.

Случайный порядок задаётся генератором с семенем `7919`.

## 7. Глубина

Режим DEPTH — отдельный запуск. План тот же, затем на горизонтальной трассе строится профиль. Ранжирование с плоским режимом не смешивается.

Глубина \(h(s)\) — до верха габарита. Обычная отметка 3,0 м, минимум 0,7 м. Потолка и шага нет. Длина в смете и в предельном пробеге остаётся горизонтальной. Уклон не круче 0,10. Профиль строится на 0,99 этого предела, чтобы округление длины до 0,01 м не опубликовало более крутой уклон.

\[
K^{\mathrm{гл}}(h) =
\begin{cases}
1, & h \le 3, \\
1 + 0{,}10\,(h - 3), & h > 3.
\end{cases}
\]

На равномерном уклоне берётся среднее по концам. Участок через 3,0 м делится, в точке деления — технический узел.

На пересечении глубина лежит в одном из двух окон. \(H\) — высота нашего габарита по таблице 1.

| объект | сверху, \(h \le\) | снизу, \(h \ge\) |
|---|---|---|
| газ, верх 2,8 м, тело 0,40 м, просвет 0,2 м | \(2{,}6 - H\) | 3,4 |
| кабель до 35 кВ, верх 2,7 м, тело 0,20 м, просвет 0,5 м | \(2{,}2 - H\) | 3,4 |
| существующая теплосеть без врезки, верх 3,0 м, просвет 0,5 м | \(2{,}5 - H\) | \(3{,}0 + H_{\mathrm{сущ}} + 0{,}5\) |

Дорога требует \(h \ge 1{,}0\) под объектом, трамвай — \(h \ge 1{,}2\). Обычные 3,0 м это закрывают. Из допустимых окон берётся отметка с меньшим \(K^{\mathrm{гл}}\), при равном коэффициенте — ближайшая к 3,0 м.

Между закреплёнными отметками профиль — ближайшая к 3,0 м функция внутри конусов уклона. Смена уклона даёт технический узел. Узел бесплатный и пробег DN не обнуляет.

## 8. Что гарантируется

- При \(K^{\mathrm{гл}} = 1\) и режиме минимальной стоимости порядок по \(J\) совпадает с порядком по S.
- Кратчайший путь в графе видимости совпадает с кратчайшим путём среди многоугольников запретов, с запасом упрощения 0,3 м.
- Динамика по группе оптимальна для своего суррогата внутри окна.
- В файл попадает полная смета: DN, камеры, врезки, штраф, \(K^{\mathrm{спец}}\), \(K^{\mathrm{гл}}\).

Глобальный минимум S поиск не доказывает. Бюджет конечен, группа в динамике не больше восьми ОКС, суррогат не содержит предельный пробег. Ширина коридора на время поиска взята по DN суммы расходов, не по DN каждого ребра.

Снимок конкурсного набора, бюджет 12 с, 17 из 17 ОКС, врезок в существующие камеры нет:

| подпись | C, ₽ | L, м | S |

| Минимальная стоимость | 248 546 610 | 1784,1 | 12,312 |
| Минимум врезок | 252 093 904 | 1831,7 | 12,554 |

## 9. Как это держится в сервисе

Поиск по бюджету в любой момент хранит лучший найденный лес и отдаёт его, когда время вышло. Если для отдельной точки допустимого маршрута нет, остальные подключения сохраняются, а в смету входит штраф раздела 6.

Память контейнеров: PostgreSQL 2 ГБ, JVM до 12 ГБ (`-Xmx12g`, G1). Файл до 3 ГБ разбирается потоково. После разбора сцена участвует в поиске целиком. Городской экстракт на 3 ГБ внутри этой памяти не обещается.

При падении контейнер приложения перезапускается (`restart: on-failure`). Приложение ждёт готовности PostgreSQL.

Если во входе нет `upstream_object_id`, цепочка существующей сети к источнику восстанавливается стыковкой концов в окне 4 м. Расчётный DN коридора берётся по сумме расходов, не по константе района.

Справочники приложения лежат в `config/appendix.yml` и монтируются в контейнер: правка файла и перезапуск не требуют пересборки образа. Правило камеры 10 м, смежность 4, вертикальные просветы и веса поиска заданы в коде по приложению и по цели \(J\).

Длины считаются в EPSG:32637, UTM зоны 37N. В GeoJSON уходит WGS 84, координата Z в геометрию не пишется.

Подъём: `docker-compose up --build -d` на Ubuntu Server 22.04, docker-compose 1.29.2, Java 11, PostgreSQL 16. Карта — http://localhost:8080, описание полей — http://localhost:8080/api.html, Swagger — http://localhost:8080/swagger-ui.html. Публичного стенда нет.

## 10. Дальнейшее развитие

В сданный сервис это не входит.

- Группы больше восьми ОКС: точная динамика остаётся для \(k \le 8\), для 9–20 — приближение Штейнера в графе с оценкой \(2 - 2/k\), дальше — разбиение на группы по восемь.
- Предельный пробег и монотонность DN внутри окна: суррогат перебирает деревья, несколько лучших кандидатов пересчитываются с реальными DN до возврата в лес.
- Режимы на разных ядрах, каждый со своим бюджетом.
- Инкрементальное обновление рёбер окна и пространственный индекс для пар, у которых нет общей касательной.
- Гидравлика после назначения DN: потери напора как проверка, при нехватке напора — подъём DN и пересчёт сметы.
- Выгрузка DXF, PDF продольного профиля и спецификации в таблицу.
- Обмен с ГИС эксплуатации.
